# P03 slice 2 — proposed negotiated leaf broker v1 contract

Status: design staging only, 2026-10-01. No implementation, linking, build, runtime proof or native extraction is claimed. Root accepted the routine choices in this card on2026-10-01; the DTO/signature freeze and review still precede parallel implementation. Slice1 remains private transport support and must pass its own gates first. This card resolves the incompatible subset/equality wording and stale ownership assumptions in the older broker proposal; those files are source inputs, not executable acceptance evidence.

## 1. Decisions and compatibility

There are at most32 declarations/grants per selected binding, at most32 unique operations per service, service names1–128 UTF-8 bytes and operation names1–256 bytes. Each `(name,version)` is unique. Integer versions are exact, not semver ranges. Unknown declaration versions/fields, duplicate descriptors/operations and invalid UTF-8/size/zero limits fail before spawn. Do not add a generic URI/HTTP, credential or filesystem service merely because a manifest requests it.

The host's immutable binding/package selection, actual provider instance and registered native service determine available authority. User configuration and manifest metadata cannot construct `HostDependencyAuthority`, a grant or an operation context. An optional dependency may be absent only when the worker actually supports that mode. A required service failure has no native fallback, alternate executable or hidden reconnect.

## 2. Offer, acknowledgement and identities

A host registry contains allowed typed descriptors, service implementations, live authority objects and per-operation limits. Registry availability is separate from package requirements. Resolve requirements once per immutable connection before spawn; offer only the exact declared operations that this binding is allowed to use. Optional service with incomplete operation support is omitted as a whole, not partially granted. Required incomplete operation support fails activation. Never offer extra registered services “for convenience”.

The broker extension offer contains: `version`, `connection` (opaque incarnation), exact `limits`, and `services:[{name,version,operations,authority}]`. Acknowledgement echoes the same connection, limit values and complete service grant identities/operation sets. Authority/connection handles are opaque, redacted, nonpersistent and issued from cryptographically strong host randomness; use the workspace UUID-v4 facility with its actual dependency/lock/Bazel updates rather than home-grown randomness. Add checked counters for IDs/generations; exhaustion closes new admission, never wraps/reuses/saturates.

Each admitted scoped ordinary parent is bound to `(connection, ordinary_parent_id, request_generation, owner_generation, opaque_context_handle)`. Host-only state additionally retains the selected binding, owner identity, provider instance, monotonic deadline, explicit cancellation, permitted grant set and immutable typed request dependencies. Wire generations only echo host-issued values; they grant nothing by themselves. Wire and Debug/log output never include the host request-context object, credentials, raw provider responses, account IDs, headers or credential-bearing URLs.

Plain `connect`/`stdio` remain plain. A worker using `stdio_with_services` must fail before domain readiness when a required broker/descriptor/limit is missing. An old plain peer may ignore an offered optional extension only when every declared requirement is optional; the host records broker disabled, issues no scopes and sends no broker frames. If it acknowledges broker1, equality is mandatory. A peer that did not acknowledge cannot use any broker frame or `broker_context` field.

Decode negotiated frames and handshake extension objects from original raw bytes. A discriminant probe may select a schema, but the final strict parser must see the original bytes: never reconstruct through `serde_json::Value` and erase duplicate keys. Plain framing keeps existing validation. The first v1 negotiation permits no midconnection grant/limit mutation; change requires a new connection/incarnation.

## 3. Typed admission, operation and cleanup facts

Proposed public result shape (names are local API, not reuse of the search contract):

```text
DependencyOutcome<T> {
  dispatch: NotSent | Rejected | Admitted | Unknown,
  operation: Result<T, DependencyFailure>,
  cleanup: Settled | Unconfirmed(CleanupFailure)
}
```

`NotSent`: local synchronous rejection before ID commitment/enqueue; no bytes or service work dispatched. `Rejected`: a correlated host receipt says the invocation was refused before broker work admission; fixed bounded frame draining is transport work, not a service invocation. `Admitted`: the host atomically owns the input/response/work reservations before spooling/decoding or invoking a handler; a later decode error does not rewrite admission. `Unknown`: a request might have crossed the process boundary but its admission fact was lost. Local successful enqueue alone cannot prove remote Admitted; missing acknowledgement cannot prove NotSent/Rejected.

A successful correlated body implies Admitted. A host error carries its actual Rejected/Admitted fact. EOF/runtime loss before a fact arrives remains Unknown even when the local writer knows that it flushed. Preserve exact dispatch facts through wrappers; never infer them from late closing flags or error strings. `Rejected + Settled` also requires local serializer/discard ownership to settle, not only a remote refusal.

Separate canonical typed failures: ServiceUnavailable, UnsupportedVersion, InvalidRequest, ReentrantCall, Busy, ResourceExhausted(resource), Cancelled, DeadlineExceeded, OwnerChanged, AuthorityRevoked, ServiceFailure, ProtocolLost, RuntimeLost. Resources distinguish request bytes, response bytes, aggregate spool bytes, decoded nodes/string bytes and admitted/work slots. Keep existing local PayloadLimitExceeded type fidelity in ordinary wrappers. Remote codes/text cannot impersonate a locally observed never-submitted or local-size error; origin is attached by the receiving runtime and remote diagnostic text is never trusted for classification.

Operation outcome and cleanup proof are independent. A known ResourceExhausted/owner/service error survives a later decoder/serializer panic, flush failure or cleanup deadline. An operation may have returned a value while cleanup becomes Unconfirmed; such a value must not be published as an accepted successful result. Record first known real operation cause under the same ledger lock as state transition, then propagate that retained cause to parent/connection observers outside locks. Do not substitute synthetic Closed/Cancelled consequences ahead of an already known cause. Intentional cancellation has a recorded origin, not a message match.

`Settled` covers the admitted broker work described below, including agreed trusted-peer receipts. It does not prove durable state, rollback of an external request, arbitrary unregistered threads/descendants, or that a malicious peer told the truth. It is not a generic promise that all existing plain-session `spawn_blocking` work is joined. Direct-child reap and broker task settlement are separate facts; forced termination can prove the former while leaving the latter Unconfirmed.

Admission and result observation must be distinct APIs. Recommend synchronous `try_begin_call(...) -> Result<PendingDependencyCall, DependencyAdmissionError>`, with a passive `finish(self)` and a cloneable exact-call control. `request_cancel()` latches idempotent intent without waiting; `cancel_and_wait()` observes the one retained immutable outcome. Dropping/not polling `PendingDependencyCall` abandons observation only. It neither retries work, revokes the parent nor disconnects siblings. Accepted calls retain all permits until their supervised settlement/discard boundary. Before any spawn, construct the owner-loss guard and first-cause cell so runtime loss before first poll cannot leak capacity or invent a successful join.

## 4. Parent, owner and connection lifecycle

A parent context is created transactionally with ordinary request ID/capacity/enqueue. Any scope/limit failure rolls back all reservations before committing an ID. The context outlives the caller's future and host request-context values remain retained while reverse work uses them.

| Event | Admission effect | Retained work and authority |
| --- | --- | --- |
| Result waiter dropped/times out | None by itself | Accepted parent/reverse calls keep owners; passive timeout is observation failure, not cancellation/remote completion. |
| Explicit reverse-call cancellation | Close only this call's admission/terminal race | Signal its parser/handler/serializer, retain/settle its response and receipt. Parent/grant/sibling remain valid. |
| Parent cancellation, authoritative deadline or parent terminal received | Retire that exact parent under the same lock as reverse admission | Reject new reverse starts for it; cancel and drain its children, decoding, destructors and physical receipts before releasing context. Connection grant stays reusable for another authorized parent. |
| Live owner/policy revocation | Fence affected grants/owners and parent contexts atomically with authority epoch publication | Wake actual in-flight service cancellation/network revocation, preserve unrelated grants. Token rotation retaining owner is distinct from owner replacement. |
| Graceful connection close | Stop new ordinary parents; admit needed reverse work for already accepted parents until each parent's retirement | Keep independent reader/writer/control paths alive while accepted parents drain. Only then revoke connection grants and complete plain shutdown/reap. |
| EOF, protocol/task loss or forced close | Revoke connection incarnation, deny every new context/call | Cancel owned work, retain/quarantine unresolved budgets and causes, report Unconfirmed if joins/receipts do not settle. Never resurrect through reconnect. |

Host deadlines use monotonic `Instant` in host memory. Composition supplies the parent deadline; a wire remaining-duration hint is advisory and cannot extend it. An optional per-call duration can only shorten the parent/service ceiling. Deadline expiry latches cancellation at the authority owner, irrespective of whether an observer is polling. Cleanup receives a separate bounded grace after operation expiry. Recommended diagnostic defaults:30-second operation ceiling,5-second broker drain grace inside the enclosing session/launcher budget. Do not copy the stale hardcoded2-second teardown into native catalog/GUI policy. Native endpoint timeout and launcher/storage cleanup budgets remain authoritative; v1 must fit them, not silently replace them.

No mutex is held across a service call, callback, await, serializer/parser join, hook or destructor. Admission locks have one documented order; revoke/terminal intent and reverse admission share a linearization point. Join owners never await their own task token. An owner-loss guard preserves known operation failure independently of cleanup uncertainty. An unresolved entry stays quarantined; subsequent calls cannot reclaim its budget merely because a waiter timed out.

## 5. Complete ownership chain and wire additions

One independent owned reader and one physical writer per direction demultiplex ordinary and reverse namespaces. Numeric ID1 can exist in both namespaces without aliasing. Allocation, duplicate tracking, pending, assemblies and terminal receipts are separate per origin. Keep monotonic IDs plus bounded holes/completed watermark; no forever-growing cancellation tombstone set. Late cancellation of a known completed ID is harmless; an ID never issued/admitted is a protocol error. Zero, overflow, reuse and excessive out-of-order gaps are rejected.

The request chain is: local reservation → joined bounded serialization → request-start admission and spool reservation → bounded assembly → owned bounded decode → authority validation → handler construction/poll/destruction → owned bounded response serialization → physical terminal flush → component owned decode/discard → component receipt flush → host receipt observation. The same call/context record moves through these states; removal at an intermediate wire end is forbidden.

Host validation runs before expensive admission and again before invoking the service. The actual service checks live authority while acquiring credentials/network permission and after the await. The writer checks the retained authority/cancellation before publishing a success terminal. Revocation cannot retract bytes already written: preserve generation/owner stamps, discard partial/stale results and fence actual domain publication against the current authority. Do not claim a wire receipt freezes policy or eliminates the native catalog's final host publication check.

Proposed additional broker1-only frames:

| Frame / direction | Required content and rule |
| --- | --- |
| `broker_request_start`, component→host | ID, exact grant/service/version/method, connection/context/parent IDs and generations, declared request bytes. Validate and reserve before spool creation. |
| `broker_result_start`, host→component | ID and declared response bytes; correlated admitted call and its response reservation must exist. |
| `broker_chunk`, `broker_end` | Preserve192KiB decoded chunk and4MiB physical-frame limits, exact order/byte/chunk accounting. Direction/start type supplies the reverse namespace. A complete valid result supplies successful host-local settlement; no “terminal” before serializer/handler destruction and physical end flush. |
| `broker_error`, host→component | ID, Rejected/Admitted, typed operation error and host-local Settled/Unconfirmed. Fixed bounded secret-safe metadata. Replaces an incomplete result for the same call; old completed/error IDs cannot be reopened. |
| `broker_cancel`, component→host | Exact own reverse ID. Coalesced pre-reserved intent; no new request ID or ordinary capacity acquisition. |
| `broker_receipt`, component→host | Exact ID plus owned decode/discard outcome and local Settled/Unconfirmed. Sent after the actual decoder and payload drop settle, including abandoned observers. Duplicate/inconsistent receipt is invalid. This is receiver ownership proof, not application durability or evidence the caller used the returned value. |

On the component, decoding the host result is owned before it can be returned to the public future. A failed/abandoned decode still has a retained owner, cleans/discards its spool and emits the bounded receipt when possible. A decoded value transfers out of the broker budget only on successful handoff; otherwise the retained task destroys it before release. The result observer can report Settled only after its receipt's physical flush, and the host frees its parent reservation only after receipt observation. The reader must remain available throughout this exchange.

Parent terminal received early is a candidate result, not immediate public success. Fence new reverse admission; cancel/drain existing children. Retain host parent result decoding and the host-only request context through joined decode and publication/discard. On the component, parent request decode and parent response serialization also remain owned in broker mode; dropping `next`/`respond` observers must not detach a parser. A dropped/failed reverse flush/receipt causes typed parent uncertainty; service errors that the component actually observes and handles do not automatically poison unrelated parents or prohibit legitimate domain error handling.

The receipt lane is reserved per admitted reverse call and independent of ordinary request capacity and host response capacity. Thus a parent may wait for children without preventing the reader from receiving their replies or the writer from flushing receipts. Bounded cancellation/error frames can finish even when body/handler work is saturated. No handler waits on the same parent completion it is required to unblock.

## 6. Reverse resource ledger and recommended profiles

Admission reserves both input storage and the operation's maximum response storage before starting expensive work. This prevents every handler holding an input reservation while all wait forever for output space. A client reserves its complete declared serialized request and negotiated response maximum before committing an ID; the host reserves the same logical maxima on request-start. Reserve response/error/receipt ownership independently from application data. Returned buffers/spools retain charges until final decode/discard/flush/receipt obligations end. Reject declared over-limit frames before disk allocation; never enforce8MiB only after receiving the full spool.

| Axis | Bounded leaf infrastructure recommendation | Diagnostic acceptance profile |
| --- | --- | --- |
| Grants / operations |32 /32; existing staged name/operation byte limits |2 grants with disjoint scopes |
| Reverse outstanding per connection |16, counts assembling/decoding/running/encoding/receipt-pending calls together |4, plus a16-slot saturation scenario |
| Ordinary/cleanup capacity |Existing32+32, not borrowed for reverse responses |Unchanged; fill32 parents to exercise progress |
| Request / response body ceiling |Explicit per-service method; transport defaults8MiB request /16MiB response only for opted-in broker operations |64KiB request /1MiB response |
| Aggregate reverse spool bytes per endpoint connection |128MiB, reservations count input plus response ceiling; therefore16 slots is an upper bound, not guaranteed16 maximum-sized concurrent calls |8MiB with exact-boundary/exhaustion tests |
| Shared process reverse ledger |16 broker-enabled connections,64 calls /512MiB aggregate spool; shared by all broker-enabled connections in that process |2 connections,8 calls /16MiB |
| Decoded structures |Per connection262,144 JSON nodes and32MiB aggregate decoded UTF-8/key bytes; process1,048,576 nodes/128MiB |Tight finite limits with meaningful JSON shape exhaustion |
| Owned blocking work |Per connection at most2 reverse decoders and2 reverse serializers running, bounded attached jobs≤admitted calls; shared process at most8 running |1 decoder/1 serializer to prove controlled pending/drop paths |
| Control/receipt queues |One coalesced cancellation and one completion/receipt reservation per reverse call; fixed metadata frames≤4KiB |Fully saturated to prove no capacity borrowing |

Broker connection permits are acquired before spawn/handshake, independently of reverse-call permits. Each permit covers the bounded descriptor/context bookkeeping and maximum per-direction physical frame staging, even for an idle connection. A failed handshake releases only after confirmed child/startup cleanup; uncertain owners retain a quarantined permit. Do not create a fresh process ledger per connection or release a permit merely because the public constructor was abandoned. Existing plain connection/history behavior is unchanged.

All arithmetic is checked; zero/overflow and configurations unable to fit one maximum request+response fail before spawn. Host chooses offer limits within its ceilings and any advertised worker ceilings; the worker verifies its actual local ceilings before ready. A worker cannot silently clamp a grant after ready; reject incompatible offers or have the host choose a new smaller immutable offer before activation. Global host and component endpoint ledgers are distinct; each charges its own copy, not an imaginary cross-process RSS total.

The JSON decode cap must count before building the returned nodes/strings. Prefer a bounded preflight/counting decode followed by materialization against an exact node/string reservation; define JSON nodes as containers plus values, and charge object-key UTF-8 bytes too. A custom typed decoder may charge the same ledger directly. A serde visitor that receives an already allocated String is not by itself a preallocation guarantee: bound/prepay parser scratch separately from returned structures using the declared raw-body ceiling, and record that pinned implementation assumption. Checking a fully materialized Value afterward is not the allocation gate. Enforce serialization counting during writes, not after an oversized temporary file exists. Do not spawn a blocking task merely to wait for a permit: jobs live in already charged bounded state. Service output allocations before serialization and values owned by the caller before admission/after handoff are explicit exclusions; a domain service must supply its own budget before claiming its application heap is bounded. These quotas bound logical storage/structure/work, not allocator/RSS, native HTTP-client caches, OS thread stacks or all ordinary histories.

Keep at least one reserved reverse-codec progress class separate from ordinary parent serialization/parsing; otherwise large ordinary histories can consume every blocking permit needed for their reverse completion. Count both classes in the process total; guarantee cancellation/error/receipt paths do not require a body-codec worker. Writer fairness is one bounded physical chunk per ready data lane, with coalesced controls serviced first and no unbounded control backlog. Tests must show data also progresses under repeated legal cancellation traffic.

These are proposed infrastructure ceilings, not measured native catalog limits. The existing endpoint's1MiB cap applies only when `model_catalog_url` is configured; the default remote endpoint currently passes no body cap. It does not justify a hidden1MiB broker response or catalog snapshot limit. Before selecting the native catalog, its contract must choose and test model-count/serialized-size/cache limits and an explicit ResourceExhausted outcome. Ordinary history and media remain governed by existing explicit SessionPayloadLimits, whose unlimited defaults this slice must not narrow.

## 7. Leaf restriction and exact guard inventory

A host leaf can use existing native HTTP/auth/network policy dependencies and the explicitly allowed one-invocation auth component path. It cannot create or await any persistent component constructor/request/release/close, including another component or a retained clone of its own caller. Do not add persistent search to thread-storage through this first leaf broker. A future acyclic dependency graph needs bounded depth/edges, authority propagation and capacity proofs.

Guard host service *future construction, polling and destruction*, not only `.await`: `HostDependencyService::call` can run code while constructing its returned future. Install the marker inside the retained task before calling it. Publish its completion guard before spawning. User helper tasks do not automatically inherit Tokio task-local markers; service implementations must preserve ancestry when using an approved helper-spawn API, and arbitrary task-spawning escape is explicitly prohibited. This restriction is enforceable for reviewed implementations, not a hostile-code sandbox.

| Current central path | Required check / cleanup exception |
| --- | --- |
| `session_supervisor.rs::connect_with_options` and future broker mode | Check before validation/spawn; all connect/connect_with_limits/broker wrappers converge here. No separate stale broker spawn implementation. |
| `session.rs::start` and new scoped admission | Check before payload serialization/capacity waiting/ID assignment. Covers call, start_with_cleanup, call_with_cleanup and new scoped entrypoints. |
| `session.rs::DeferredControl::{release,release_reply}` | Reject explicit enqueue-and-wait callback before consuming reservations. Private Drop queues only its already authorized cleanup, cannot grant authority or create another service. |
| `session_reply.rs::PendingComponentReply::wait` | Reject persistent wait from a leaf before it can wait on or start legacy decode; broker mode's decode is independently owned regardless. |
| `session.rs::ComponentSession::{begin_close,close}` | Guard before initiating connection shutdown or subscribing/waiting; begin_close returns Result. Private retained-owner shutdown/Drop bypass only performs previously authorized cleanup. |
| New `DependencyClient` begin/wait and server broker admission | No implicit nested host-leaf callback; exact scope/grant validation still runs. Cancellation-only control is nonblocking preauthorized cleanup; awaiting another persistent owner is not. |
| `session_server.rs` broker `stdio/next/respond/finish` management | Prevent a leaf using persistent server management as an alternate I/O/wait path. Owned internal reader/writer/cleanup actions remain private and run without user callback under ledger locks. |

The bound source inventory contains13 lexical `begin_close` hits in seven paths. Direct ComponentSession callers include active host close/tests, file-search `ProviderOwnerGuard::drop`, thread-store `AcquisitionFence::drop` and void `begin_shutdown_store`; staged replay wrappers are not active extraction. Drop/void callers cannot simply propagate a new Result. Recommend a guarded, pre-admission reservation of an opaque single-use shutdown-on-drop owner: its private Drop can only signal the exact already authorized session shutdown, and successful acquisition may disarm it. No unrestricted public bypass method or new service/start capability is exposed. Active void adapters retain any guarded rejection for their awaited shutdown receipt. Resolve receiver types and migrate each caller explicitly; do not blanket-add `let _ =` or `unwrap` and obscure a denied shutdown. Preserve the current private `SessionInner::Drop` and preauthorized `DeferredControl::Drop` behavior. Test constructors, held sessions, held pending replies and Drop cleanup separately; a constructor-only test is insufficient.

## 8. Source interfaces and dependency direction

`component-api` should own only bounded serializable requirement/offer/error DTOs needed by external SDKs; no provider/auth/HTTP or runtime types. `component-host` owns registry/authority objects, ledger, process supervision, wire demultiplexing and retained work. Keep detailed codecs/IDs private and export the minimum scoped client/server/service API. Service-version schemas belong to domain API crates (later `model-catalog-api`). Package requirements resolve through existing catalog validation but never instantiate services.

Reuse current `ComponentSessionOptions`, `SessionPayloadLimits`, `SessionFailure`/paired reply semantics and `session_supervisor` child owner. The new plain/shared private codec seam comes from accepted slice1. Stale `broker_connection`, `broker_wire`, `broker_writer`, `broker_completion`, `broker_decode`, `broker_spool`, `broker_client` are implementation ideas to rebase, not patches to apply verbatim. Required client completion differs from their waiter-owned decode; required limits differ from their post-spool8MiB check. No new shared crate is needed merely to move these private modules.

Native model-provider composition later supplies the actual configured `ModelsEndpointClient`, `AuthManager` policy/owner watch and immutable per-call `HttpClientFactory` through host-only context. Broker infra must neither import those crates nor recreate them from JSON. `create_catalog_dependencies` remains unlinked and cannot serve as proof. Native monotonic workspace-policy publication, owner-preserving token refresh, post-cache-write validation and atomic mirror publication are catalog/P04 prerequisites, not solved by opaque broker handles.

## 9. Review-sized implementation order after root agreement

1. **Contracts / validation only:** DTOs, exact declarations/grant equality, limits validation, error/dispatch/cleanup facts and source-API migration plan. Broker still disabled; ordinary manifest regression. Keep each semantic diff below~500 changed lines where feasible.
2. **Local authority/ledger:** bounded grant/context/call reservations, checked IDs, live revocation and root-context ownership; deterministic no-spawn admission tests. No transport claim.
3. **Retained byte/work owners:** decoder/serializer/discard queues, first-cause/owner-loss guards, counters and independent progress classes. Gate with actual blocking readers/writers and destructors; quarantine failure. No remote claim.
4. **Negotiated codec/demux:** raw extension parsing, separate namespaces, bounded admission-before-spool and receipt frames; pipe tests at saturation, duplicate/truncated data and exact byte counts. Plain mode remains default.
5. **Host activation:** reuse retained startup/options; scoped parent admission/completion and all centralized leaf guards; preserve typed failure/reap and dropped startup owners. No native domain selection.
6. **Component server/client activation:** one owned reader/writer, retained reverse response decode and receipt, per-parent drain and public passive handles. Link host and server only at a coordinated checkpoint. Apply required Cargo/lock/Bazel changes together.
7. **Independent installed diagnostic consumer:** build outside source using SDK, park export/target, install after host frozen, prove genuine reverse call and capability addition without host recompilation; same worker/host hashes across lifecycle cases. This is infrastructure/additive capability, not native extraction.
8. **Shared runtime regression and documentation:** old plain search/storage workers, selected/default/removal, failed handshake/config, manager Launch Ctrl+C, GUI Stop/recovery where shared lifecycle is affected. Record raw failures, source/binary maps, package/version compatibility and limits.
9. **Native catalog contract review:** only now select catalog-specific caps/authority policy/early manager composition and native ownership extraction. Do not silently drop general Session/model-v2/P04 dependencies from the canonical roadmap.

Parallelism is safe only after the DTO/lifecycle/limits card and module ownership are agreed: ledger/authority, retained-codec work and SDK/raw-frame fixtures can proceed against frozen signatures. Root owns shared session/server activation and all serialized validation. Do not parallel-edit central state types or claim a collection of unlinked tests is an accepted checkpoint.

## 10. Required acceptance and remaining domain decisions

Infrastructure tests: old manifest absence and old strict-host rejection of declared broker; missing/optional service; exact/extra/narrowed/duplicate grants; raw duplicate handshake/frame fields; wrong connection/parent/grant/generation; counter exhaustion; both namespaces ID1;32 occupied forward parents with reverse responses/cancellation/receipts progressing; per-connection and shared-global spool/node/work exhaustion; no allocation before admission; destructor/parser/serializer/flush/receipt held while parent terminates; unpolled result/cleanup observer loss; runtime loss before first poll; original operation error plus later cleanup error; owner-revoke A→B→A and unrelated sibling grant; receipt never arrives; graceful drain and forced direct-child reap with Unconfirmed work. Prove all exposed persistent paths reject reentry, while already authorized Drop cleanup remains available.

Real external-process tests must include held response decoding and final flush on both sides, not only mocks or wire arrival. For D7, hold the component decoder after complete wire input and send/attempt the parent response: host context/capacity cannot release before receipt; after release all exact counters return to baseline. Abandon the decoder waiter and repeat. Force process loss and assert uncertainty rather than returning the same capacity as cleanly joined. Keep existing strict subreaper assertions and unchanged original peers.

Domain decisions still required before native catalog adoption: exact fetch/owner-validation schema and capability provenance; which operations are optional for static/Bedrock/custom catalogs; native request/response/model-count/cache caps and migration/rollback; deadline compatibility; native authority-policy epoch publication; request-time HTTP context retention; actual owner-fenced cache and host mirror publication; early models-manager construction plus isolated-session bypass. The generic diagnostic defaults above do not authorize credentials, a generic HTTP grant, changes to native catalog semantics, or inference replacement.
