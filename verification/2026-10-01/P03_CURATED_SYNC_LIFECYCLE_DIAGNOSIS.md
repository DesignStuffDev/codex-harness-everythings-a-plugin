# Native curated-plugin sync lifecycle diagnosis

This is a read-only audit and proposed repair contract, not an implementation or a passing runtime checkpoint. The four relevant production files are byte-identical to upstream `d42056091aded7feb1d88ac7e83972108b2aa478`; exact hashes and immutable failed-run input hashes are in `audit.json`. The current source-owner source checkpoint is `99e6802fd478e55686559aefdd6ae79177a45397`.

## Observed failure

Both `p03-source-owner-newhost-storage` and `-02` completed the existing storage acceptance command with exit 0 (13 behavioral commands), then failed the unchanged default five-second subreaper drain with exit 125: descendants remained. These are failed overall acceptance attempts, not full passes. The unchanged package/functionality checks do not establish a clean host shutdown.

The sampled second attempt observed real, live native Git/HTTPS descendants while the strict runner drained. PID 825726 was still sleeping after adoption by PID 1 at sample time 12.782 seconds. Descendant PID 825808 remained running/sleeping through 14.285 seconds. Later disappearance or zombie state does not cure this failure. The sampler did not retain argv, so do not label a particular PID as an exactly traced fetch/index-pack command. The native Git and HTTPS process shape, inherited group ID, and unfinished `CODEX_HOME/.tmp/plugins-clone-*` directories strongly match curated startup sync. The two failed homes contain respectively four and three such incomplete staged directories, plus the sync lock. No fallback/runtime subprocess was started during this audit.

`/usr/local/bin/git` and `/usr/local/libexec/git-core/git` resolve to the SAME device/inode native ELF with 147 hardlinks. Calling one a wrapper and the other the real executable is unsupported. The process chain can be Git invoking its own internal subcommands and HTTP helper.

Earlier cache-revision acceptance passed with a `/tmp` workdir; the newer runs used `/workspace` because `/tmp` filled. There is no evidence that the path itself causes the failure. Default startup networking, response timing, filesystem performance and CLI exit timing can expose this existing ownership gap nondeterministically. Do not report an environment-only explanation or repeat the expensive fixture blindly.

## Source ownership gap

All paths below are relative to the repository root.

- `codex-rs/features/src/lib.rs:1477`: the native `plugins` feature is enabled by default. This is distinct from the custom component packages under test.
- `codex-rs/core-plugins/src/manager.rs:748`: an enabled local/API plugin configuration starts curated sync if marketplace policy permits its upstream Git URL.
- `codex-rs/core-plugins/src/manager.rs:3287`: `start_curated_repo_sync` starts a named native thread and discards its `JoinHandle`. The worker retains `Arc<PluginsManager>`. There is no explicit shutdown/cancellation/drain API for it; manager drop cannot be relied on while its worker retains that Arc.
- `codex-rs/core-plugins/src/startup_sync.rs:610`: initial `ls-remote` uses a trusted temporary Git repository under the isolated Codex home. Fetch then creates the observed `plugins-clone-*` staging directories (`:185`, `:256`).
- `codex-rs/core-plugins/src/startup_sync.rs:683`: `run_git_command_with_timeout` owns a plain `std::process::Child`, inherits the caller's process group, and polls up to 30 seconds. It kills only the direct child on timeout. Normal host process exit destroys the detached native thread without executing its Rust cleanup, so its child may outlive the host. A plain Child drop is also not a tree-kill contract.
- The same function waits for child completion before draining piped stdout/stderr. A sufficiently verbose child can block on a full pipe. Killing only its parent then calling `wait_with_output` can still hang on pipe descriptors held by descendants. `git_head_sha` at `:640` additionally uses unbounded `.output()` outside that helper.
- `startup_sync.rs:169` uses a blocking file lock. HTTP GitHub/export fallbacks create a current-thread runtime and apply individual 30-second request timeouts (`:307`, `:340`, `:972`, `:995`, `:1015`), but provide no host cancellation. Per-request timeouts do not bound overall shutdown across requests, extraction and filesystem publication.
- `codex-rs/git-utils/src/git_process.rs:33` already sets an isolated process group and drop guard for its asynchronous metadata commands. Its different observed group behavior helps distinguish it from this startup path. Reuse principles/contracts where useful; do not assume copying it alone solves native-thread ownership, pipe pressure, or post-parent helper lifetime.
- `codex-rs/core-plugins/src/git_policy.rs:37` and `startup_sync.rs:665` preserve trusted system Git/PATH, scrub repository-local Git overrides, prevent workspace helper injection, retain current network policy, and disable prompting. These security boundaries must remain unchanged.

## Proposed bounded repair contract (not yet implemented)

1. Add an explicitly owned curated-sync lifecycle object in the existing core-plugins boundary. Admit at most the permitted sync generation; retain cancellation state, completion/result and native JoinHandle until joined. Fence new sync admissions before shutdown. Concurrent/repeated shutdown must share the same completion and earliest deadline. Worker captures must not create an ownership cycle that prevents cancellation. No long join or callback under manager locks and no blocking joins on Tokio executor threads.
2. Expose request-cancel and bounded async finish operations through the owning manager/ThreadManager path. Preserve normal startup behavior. Add a guard for early error/drop paths that requests cancellation; the application shutdown path must actually await/drain it. Merely adding Drop to a still-retained manager is insufficient. Distinguish successful drain, cancellation, timed-out cleanup, worker panic, and forced termination; incomplete cleanup cannot return an unqualified successful shutdown.
3. Wire BOTH real shutdown paths. `app-server/src/in_process.rs:383` bounds client shutdown; its processor cleanup at `:674` calls `MessageProcessor::drain_background_tasks` then thread shutdown. `exec/src/lib.rs:1140` and `:1318` already call that client shutdown on normal/fork and final paths. Add native plugin-background cancellation/drain to the existing processor lifecycle without skipping it on earlier cleanup errors. The external App Server path at `app-server/src/lib.rs:1340-1405` must likewise fence/cancel/drain it before reporting Graceful. Forced/second-signal paths request immediate cancellation and return uncertainty/failure as appropriate. Share remaining host deadline with native sync; do not expand the external runner drain or consume storage's documented cleanup budget. `thread_manager.rs:1439` only shuts agent threads today and does not join native plugin startup workers.
4. Each spawned Git command gets a private Unix process group or Windows job. The owner must cancel/terminate/reap its whole tree with a bounded escalation, including direct-parent exit while helpers remain. Never signal the inherited manager/test process group. Drain stdout/stderr concurrently with explicit size bounds or bounded spooling; preserve enough output to validate expected SHA and diagnose failures. No pipe wait may exceed the cancellation/deadline. Route every curated Git call, including HEAD lookup, through the same lifecycle contract. Preserve trusted executable resolution, environment scrubbing, repository isolation, proxy/TLS/network policy and noninteractive behavior. No Git wrapper bypass.
5. Make file-lock admission cancellable (try-lock/backoff with cancellation/deadline), HTTP request/body futures cancellable within their existing policy-aware runtime, and staged extraction/publication cancellation-aware. Cancellation must not enter a later fallback transport. Do not activate an incomplete directory or advance plugins.sha on cancellation. Preserve previously active snapshot and clean only owned staging resources. Joining a stopped worker provides the ownership proof.
6. Inventory adjacent native workers separately: configured marketplace auto-upgrade (`manager.rs:2836`) and non-curated cache refresh (`:3268`) also discard native JoinHandles and retain manager Arcs. Remote catalog/bundle/featured work has detached Tokio tasks around `:2892`/`:2924`. The failed fixture directly implicates the curated path only; no claim those other paths caused these failures. Prefer a lifecycle registry that can cover them in subsequent bounded changes rather than claiming all plugin background work is repaired after one worker.

If runtime proof stays blocked, publish accurate failed checkpoint evidence and retain this as the next repair priority before broader installer/authority extraction.
