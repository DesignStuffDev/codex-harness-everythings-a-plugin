# Source42 production resource checkpoint

The current login library, login integration suite and model-provider library proofs were preserved together with the compiled-only CLI library before their four output selectors were retired. The CLI library was never executed as a test. The accepted producer scopes remain focused4, full301 and provider108; focused4 is a subset of full301.

The 136,134,715-byte archive contains 563 exact members, including 421 observer records. Root verified the complete archive and a 620,733,592-byte materialized restoration before removing the four original outputs. Only that newly created verification restoration was subsequently released. Earlier archives/restorations and source/index were retained.

The component manager f054 executable was independently archived and fully restored. Its 7,290,880-byte uncompressed archive and verified restoration remain available; its original hardlink pair was retained. This is preservation of an existing executable, not a new build or runtime test.

Four ordinary grouped-test-context core/TUI library and metadata files were then retired: 442,593,280 allocated bytes. Their exact fingerprint contexts are outside the recorded normal CLI 1,338-record and manager 86-record dependency closures. Normal core f409/TUI ca2 variants remain the selected production contexts. These are reproducible test build caches, not source or proof executables; future grouped testing must rebuild them.

All resource phases retained the 8,949-file source42 map and Git index. OOM counters remained 10/5 through the completed phases and production admission. The canonical production preflight observed 1,491,427,328 free overlay bytes against the 1,458,762,560-byte estimate, 1,459,408,896 temporary bytes, 1,781,473,280 hard-unused memory bytes and 3,928,956,928 conditional effective bytes. The output estimate includes a 256 MiB reserve. `/tmp` remains RAM-accounted tmpfs.

Root reported starting the production build. This checkpoint inspects only its admission receipt and makes no build-success or runtime-acceptance claim. All preservation archives described here are on the original VM; they do not establish an external backup. No active build output or large artifact payload was read to prepare these four files.

`RESOURCE_CHECKPOINT.json` holds the sanitized facts. `RECEIPT_INDEX.json` references exact completed local receipts and hashes without copying the full source maps, binary bytes, archives or observer inventory.
