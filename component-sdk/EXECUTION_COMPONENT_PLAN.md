# Native execution and approval extraction

Status: read-only design audit on 2026-09-30. No execution component is implemented by this document, and no new runtime test was run for this audit. Sources are the imported Codex revision `d42056091aded7feb1d88ac7e83972108b2aa478` plus the current working tree. This follows the context/model work; it does not expand the frozen storage checkpoint.

The next genuine native extraction should own process creation, pipe/PTY I/O, sandbox application, and process lifetime behind the existing `ExecBackend`/`ExecProcess` contracts. Preserve the host's command preparation, approval gates, terminal ownership, and model-visible tool lifecycle initially. A plugin that merely registers another JSON tool does not replace this subsystem.

`codex-exec` is the headless Codex frontend, not this execution backend.

The [native handler inventory](../codex-rs/core/src/tools/handlers/mod.rs) also contains independent families: apply-patch/file diffs, image reads, MCP calls/resources, dynamic tools, agent coordination, permissions/user interaction, plans/context windows, plugin installation and environment readiness. Extension crates own additional web-search, image-generation, agent-message-board, queue, memories, skills and Guardian behavior. These must retain their own outputs and host services; process extraction does not extract them. Existing `ToolExecutor`/extension state contracts are the starting points for their later adapters.

## Concrete gaps that must precede a replacement claim

1. **Ordinary local execution bypasses the otherwise useful trait.** [`open_session_with_prepared_exec_env`](../codex-rs/core/src/unified_exec/process_manager.rs) uses `Environment::get_exec_backend()` only for a remote environment or an executor shell snapshot. Other local calls invoke `codex_sandboxing::spawn_process` directly. [`uses_executor_managed_process_sandbox`](../codex-rs/core/src/tools/runtimes/unified_exec.rs) uses the same condition. Routing only one branch would leave common commands native. [`core::exec::execute_exec_request`](../codex-rs/core/src/exec.rs) is another direct, bounded execution path: concrete callers include [`UserShellCommandTask`](../codex-rs/core/src/tasks/user_shell.rs), [`shell_snapshot_sandbox`](../codex-rs/core/src/shell_snapshot_sandbox.rs), and [`zsh-fork escalation`](../codex-rs/core/src/tools/runtimes/zsh_fork/unix_escalation.rs). Their timeout, output and authorization semantics need separate parity cases.
2. **Placement is not locality.** `Environment::is_remote()` also controls shell snapshots, environment reconstruction, path handling, attribution, credential brokerage and Windows preparation. Do not mark a local plugin as remote merely to reach its backend. Add an explicit execution placement/capability contract and use it consistently for sandbox preparation and launch routing while retaining local environment identity. Avoid applying a sandbox twice to an already transformed command.
3. **Zsh-fork has a real descriptor contract.** `SpawnLifecycleHandle` supplies inherited descriptors and an `after_spawn` lifetime boundary. The exec-server branch explicitly rejects inherited descriptors; the zsh-fork path uses them. A descriptor number serialized to JSON is not a transfer. Preserve this as an explicit uncovered facet until either the native zsh controller and its descriptors move into the worker, or an actual platform handle-transfer channel is implemented. Selecting a backend that cannot satisfy a requested facet must fail clearly before execution; it must not silently call the host backend.
4. **Construction is closed.** `Environment::local` is crate-private and constructs `LocalProcess` itself. There is no production injected local execution owner. The public `ExecProcessEventReceiver` supports consuming events but its usable producer/replay constructor is internal (`empty()` is not a streaming implementation). Add a minimal public owned factory and bounded event producer adapter, not public access to all internals.
5. **Close currently means less than joined cleanup.** [`LocalProcess::shutdown`](../codex-rs/exec-server/src/local_process.rs) drains its map, drops `Starting` registrations, and calls synchronous `ProcessHandle::terminate` for running entries. The start path notices a removed registration and terminates a late child, but shutdown does not wait for that path. Output/exit tasks are spawned without retained join handles. `ProcessHandle::terminate` requests a kill, aborts I/O handles and deliberately detaches its child waiter so the child can still be reaped. The runtime-independent [`child_reaper`](../codex-rs/utils/pty/src/child_reaper.rs) is an additional eventual cleanup fallback. None of this proves all work has finished when `shutdown()` returns. `UnifiedExecProcess::terminate_confirmed` confirms backend termination request success, not a joined process tree. A new component close contract must not overstate these existing guarantees.
6. **Disconnect and shutdown are distinct.** The native [`SessionRegistry`](../codex-rs/exec-server/src/server/session_registry.rs) allows one attachment, retains detached sessions for 30 seconds in production, and can resume them. The server's request dispatcher aborts and joins request tasks when a connection closes. Preserve remote reconnection semantics; an explicit local component-owner shutdown must fence and finish the owned session. Do not replay `start` after an ambiguous reply: duplicate process IDs are rejected, not an idempotent start-result cache.
7. **Native helpers are a package dependency.** [`ExecServerRuntimeOptions`](../codex-rs/exec-server/src/runtime_options.rs) currently expects a Codex executable for hidden helper modes plus a Linux helper alias. [`process_sandbox`](../codex-rs/exec-server/src/process_sandbox.rs) uses these paths for arg0, sandbox launch and readable helper roots. A separately built native execution package must include compatible helper entrypoints/binaries and immutable trusted paths, or explicitly declare a versioned host helper dependency. Invoking the unchanged complete Codex engine does not satisfy native subsystem extraction.

## Proposed first contract and implementation slices

Proposed selection: `execution_backend:local`, pinned once when composing an environment. This is a new contract, not an existing registered component. Scope the instance to the environment/executor session, with process leases owned by the host terminal manager. Isolated sessions retain the existing isolated-component selection rules. A selected package/configuration failure stops startup or the affected operation without native fallback.

Reuse `ExecParams`, `ExecEnvPolicy`, `ShellSnapshotRequest`, `ProcessId`, `ByteChunk`, read/write/signal/terminate DTOs, sandbox types and exact structured errors from `codex-exec-server-protocol`. Reuse native `LocalProcess` implementation behind a small exported owner/factory, then add the component adapter and a separately built native worker package. Keep its code dependency graph free of `codex-core`. Package generation should use the existing SDK export/build/install mechanism and record pinned source/license provenance.

The data contract must retain:

- Exact argv/arg0, `PathUri` cwd, independent sandbox-policy cwd/workspace roots, environment inheritance/filtering/overrides, `tty` versus `pipe_stdin`, snapshot scope and all Windows/managed-network settings. Preserve unknown sandbox type (`None` in `ExecResponse`) versus explicitly unsandboxed (`Some(ProcessSandboxType::None)`).
- Raw bytes and stream identity; monotonically sequenced output, bounded replay, overflow recovery through `read(after_seq, ...)`, and distinct `Exited`, `Closed` and transport `Failed`. Exit can precede the final output stream close. Do not reconstruct exact event sequences merely from the final text output or collapse all failures into exit code 1.
- Stable backend process identity and host public terminal identity separately: native retry may reuse the public handle while minting a new backend ID. Preserve `write_id` duplicate suppression and the atomic accepted-write bookkeeping. An unknown write/start delivery outcome must not trigger blind replay or native fallback.
- Snapshot prewarm and actual native cache ownership. The executor owns shell capture, native shell information and protected snapshot resources; request/config generations and session scope must prevent cross-session reuse.
- Typed network-policy decisions with process/environment/attempt identity, bounded deadlines and cancellation. `NetworkPolicyDecider` remains host authority. Missing required managed-network capabilities fail closed, and a late denial can terminate a yielded process. Keep the host's deferred approval until actual process completion/cleanup, not just until the start RPC replies.

Transport recommendation: reuse the native exec-server process protocol and notification semantics behind a package-owned process endpoint, with component discovery/selection and owner lifecycle around it. Do not shoehorn event notifications through the one-shot generic tool protocol. Before implementation, agree whether the persistent component transport will gain an exact bounded process-event subscription lane or the host will own a dedicated native exec-server transport adapter; both must preserve the native sequence/replay and reverse network-decision contracts. No transport choice may create a new unauthenticated listener. Typed protocol reuse is required whichever carrier is chosen.

The **owner lifecycle** is part of the initial interface, not a follow-up:

- A synchronous admission fence prevents new starts/prewarms at close. Accepted starts remain owned independently of their RPC waiter. Pre-start cancellation is remembered, so a late successful spawn is terminated and joined even if its response was lost.
- Owner shutdown cancels scoped network callbacks and snapshot capture, terminates accepted children, joins outstanding starts, I/O, exit waiters and any blocking/helper work, then retains a close outcome for subsequent waiters. A dropped close waiter does not abandon that work. Platform process-group/job behavior and descendant ownership must be stated and tested precisely.
- A regular turn abort still leaves an already retained background terminal usable. Explicit terminal termination, network denial, session shutdown and whole executor shutdown have separate effects. Keep the original stdin-approval identity after a turn changes.
- Host transport force/reap only proves cleanup of the worker process. The worker's successful graceful close must prove its own child/task cleanup. At an exceeded deadline report cleanup unknown/forced; do not assert graceful child-tree cleanup from the worker PID alone.

Recommended code order after the context/model gate:

1. Add owner/admission/join semantics to the native process implementation with held-start, held-I/O and interrupted-close tests; keep the existing native factory as default. Extract only enough public construction/event APIs to let an external Rust crate implement the contract.
2. Build a native worker package and the selected factory/adapter. Exercise an existing executor-managed path first and label that coverage narrowly. Preserve native helper dependencies and required network callbacks. A second custom package must be independently built to prove replaceability, not just that a native binary can be moved.
3. Route ordinary local unified execution through the explicit placement contract, with one faithful sandbox/environment preparation owner. Differential tests must pass before claiming ordinary shell replacement. Follow with zsh/descriptor support and bounded direct `core::exec` callers; list each remaining bypass until removed.
4. Extract native command policy evaluation and approval orchestration as separate components using the already shared `codex-execpolicy` evaluator and extension review contract. Resolve borrowed `Session`/stores into owned inputs and scoped services before moving behavior. Host command evidence, cache identity/generation, permission enforcement, and atomic policy amendment commits remain authoritative until each has its own explicit interface. Never let review approval bypass hard permission restrictions.
5. Extract the remaining terminal-manager/tool runtime, hook orchestration, filesystem, shell discovery and environment-provider facets with typed dependencies. Keep tool-schema and lifecycle contracts shared. Agent/Code Mode/MCP tools retain their own protocol and session ownership rather than becoming arbitrary shell requests.

Completion of the initial execution-backend milestone would leave approval orchestration, terminal management, tool routing, filesystem/HTTP/environment discovery, bounded direct execution and any unsupported descriptor paths explicitly unextracted. Completion of the whole project requires closing those gaps; neither existing crates nor the first worker package alone demonstrate that outcome.
