# Next substantive native catalog checkpoint — source audit, not implementation

Recommend native model discovery/merge/file-cache ownership as the first domain extraction after the negotiated leaf broker. The smallest meaningful acceptance checkpoint is a separately built native catalog worker selected through the real host before model listing/default selection, plus a separately built custom catalog that changes an actual model choice with unchanged host bytes. A diagnostic reverse call, a new DTO crate or a native manager hidden behind an unchanged outer process is not this checkpoint. Existing catalog sources are saved drafts, unlinked and unverified.

## Independent native prerequisite that can proceed without broker activation

First patch: publish a native forced-workspace policy epoch atomically with its value snapshot at `AuthManager::set_forced_chatgpt_workspace_id`. Keep a coherent snapshot under the same native lock, publish change notification only after the value/revision transition, and let consumers validate the pair. Avoid a separately sampled value/atomic counter that permits mixed snapshots. Explicitly fail closed on revision exhaustion rather than wrap or reuse an epoch. The existing void setter and native caller compatibility need an implementation-level API review before editing. Audit native request-policy invalidation alongside this setter; do not invent a second routing policy in the component layer.

Tests must hold observations until A→B→A completes and still detect revocation; same value must not manufacture a change; concurrent setters must preserve monotonic state. Reuse existing `auth_owner_generation_distinguishes_refreshes_from_identity_changes`, `auth_owner_generation_preserves_logout_and_switches_when_coalesced` and `captured_credentials_are_revoked_if_account_changes_before_client_construction`. Add restriction changes during a held native request, while preserving same-owner credential refresh versus true owner replacement behavior. Run focused codex-login gates, then the affected native provider endpoint tests. This is a substantive native authority prerequisite/customization, not an independently replaceable component yet.

Second independent patch: expose a provider-owned catalog endpoint capability by factoring the existing ConfiguredModelProvider endpoint construction and injecting that exact endpoint into both ordinary native manager construction and future broker composition. Static/Bedrock providers return no fabricated OpenAI endpoint. Do not select provider/auth/gateway again in core or export credentials, raw headers, generic URLs or unrestricted HTTP factories. Provider capability tests can run natively with broker disabled, including no-endpoint provider behavior and request identity/routing parity. The smallest source change is an optional `ModelProvider` capability defaulting to None, used by `ConfiguredModelProvider::create_models_manager` after its explicit static-catalog short circuit (provider.rs:426). Preserve the existing Disk/Disabled/Custom branches (438–447) and `with_provider_catalog` selection (449); the actual endpoint construction at432 already owns provider info/auth/gateway managers. This factoring may proceed independently or in parallel with the policy epoch patch, but both remain required before selected remote authority.

Provider review confirms active endpoint tests for explicit/default routing, request-time proxies, residency, command auth, headers, slugs, explicit size cap and redirects; provider manager-path tests and models_identity/endpoint-timeout tests are linked. Add capability-path tests through the actual provider instead of reconstructing OpenAiModelsEndpoint directly. Existing explicit-URL response cap is1MiB only on that native path; it is not a universal catalog bound. Auth/client composition occur before the current request timeout, so do not claim that timeout covers total endpoint startup. Staged create_catalog_dependencies takes an externally supplied endpoint and registers optional services even for None; by itself it does not establish provider-owned authority.

## Review-sized extraction order after broker support

1. Complete negotiated leaf transport/retained cleanup and the two native prerequisites. Canonical roadmap still lists P03/P04 prerequisites and model-v2 obligations; explicitly document any narrow P05a catalog sequencing exception rather than silently dropping P05c inference prerequisites.
2. Rebase catalog DTOs and endpoint adapter to accepted broker types. Provider issues request-scoped `host.model_endpoint` authority using the actual endpoint and retained request HTTP policy. Required/optional services must match actual native provider capabilities. Static catalogs must not require a fabricated fetch grant merely to use a local vector; preserve owner checks through scoped host publication.
3. Implement worker-owned native OpenAiModelsManager/cache plus a bounded host mirror/controller. Retain accepted refresh/start/close independently of observers; no per-caller spawned waiter queue. Keep endpoint domain failures distinct from selected component failure. Authoritative endpoint failure clears models/ETag; transport/ownership failure must not silently fall back to native. Preserve host client-version cache key, lossless paths, finite model/snapshot bounds and nonreused revisions.
4. Add selected model-service ownership before actual listing/default selection, carrying explicit/default provenance and isolation through ThreadManager, session startup and delegates. Session cancellation closes only its owned lease; it must not revoke a shared provider. Hold acquired components through startup failure, late Ready handoff, cancellation, cache IO, snapshot decode and final shutdown receipts.
5. Export/build native worker outside the checkout, park source, install/select on a frozen real host. Exercise real endpoint fixtures with credentials kept in host. Build a custom catalog separately and demonstrate a visible model/capability change in an actual inference request. Uninstall must restore native behavior without rebuilding the host. This is the first checkpoint to label selected native catalog/cache extraction, with remaining host helpers/provider/inference/auth explicitly listed.
